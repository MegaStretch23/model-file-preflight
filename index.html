Model File Preflight

Check a downloaded AI model file before you load it. Drop a .safetensors, .gguf, .pt / .pth / .bin / .pkl (pickle or zip-based torch) or .onnx file. The page reads only the header and structure, never loads or runs the model, and lists what looks wrong: tensor offsets that overlap or run past the end, a truncated GGUF, pickle opcodes that import os, subprocess or builtins.eval, ONNX tensors that read from external files.

Private by construction. Everything runs in this page. The file is read in your browser tab, nothing is uploaded and the page code makes no network calls. This is a heuristic pre-flight, not a guarantee of safety, and it is not malware detection: a PASS means none of these checks found a problem.

What each format is checked for

  • safetensors: header length plausible and inside the file; header is JSON; each tensor has a known dtype and its byte span equals shape times dtype size; spans do not overlap, run past the end or leave gaps.
  • GGUF: magic, version, tensor and key/value counts against the file size; the metadata and tensor table parse; each tensor of a known type fits inside the file (truncation).
  • Pickle and zip-based torch: the opcode stream is read, never executed. GLOBAL, STACK_GLOBAL, INST and the REDUCE / NEWOBJ / BUILD calls on them are traced. Imports of os, posix, subprocess, socket, builtins.eval / exec and similar are a FAIL; modules outside the usual checkpoint classes are a WARN.
  • ONNX: the file parses as protobuf, has an ir_version and a graph; tensors that point to external data files are a WARN, and a location that leaves the model folder is a FAIL.
  • Any file: SHA-256 and, if you paste one, a comparison with the expected hash.

Not covered: tensor values, backdoored weights, malware inside the file, pickle tricks that need execution to reveal, and anything past the first 64 MiB of a pickle. The same checks ship as a one-file stdlib Python CLI, preflight.py, for running on a download before you load it: python3 -I preflight.py model.pt.
